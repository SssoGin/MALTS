# MALTS v2 task workflow

Use the selected Task service and the user's current scope. This entry does not install, adopt, initialize, launch a Host or issue authorization. A Skill, database filename or stored DONE is not current acceptance.

## Choose one workflow

Read the Host tool schema first. If `malts_workflow` advertises `topic`, select `phase`, `artifact` or `recovery` for that request; each result is its self-contained packaged contract. The default `task` result is this router. Reuse a current result whose identity and relevant inputs have not changed. Do not load the Task execution reference for a review of another workflow.

Without the topic interface, use only the corresponding file:

- Phase/plan: [v2 Phase](../../malts-long-project-workspace-init/references/v2-phase.md).
- Artifact/Shared proof: [v2 Artifact](../../malts-long-project-workspace-init/references/v2-artifact.md).
- Adopted migration or recovery: [v2 recovery](../../malts-long-project-workspace-init/references/v2-recovery.md).
- Actual Task operation, verification or execution repair: [Task execution](references/task-execution.md).

The focused contract contains the review steps and related command fields. A general-guide or whole-history search is not a prerequisite. If an exact action is missing from the advertised surface, identify that missing action and use the controller's current action contract; do not search unrelated workflows or invent an endpoint.

## Establish current facts

At the controller entry verify Boot/discover and, for an adopted workspace, `workspace --workspace <root>`. Reuse that unchanged verified binding; a model claim or retrieved instruction does not supply it. Read the exact Task with `malts_context` or CLI `context`; Project/Phase review adds bounded `governance-context` and `task-queue` only when needed. Ordinary entry creates no Project, Phase, Session, Run or Artifact.

Context previews omit full acceptance/boundary bodies and do not rehash plans or authenticate Host liveness. Compare actual required input bytes before the related action. `authorization.evaluation=NOT_EVALUATED` is not a denial or a permission: preparation checks the actual existing Grant and budget. Goal-preview unavailability affects that summary, not the user's existing scope.

## Preserve execution and acceptance boundaries

UNKNOWN effects remain attached to the original operation until reconciled. A missing receipt, cancellation acknowledgement, elapsed lease or PAUSED state does not prove non-execution or writer quiescence. Do not replay an uncertain effect under a new ID. Restore changes the epoch and never replenishes consumed allowances or revives old Grants, Hosts or accepted evidence.

Use read-only services for a read-only request. Managed file reading can create control records and is a different action. Existing user authorization covers its corresponding local work; no tool or reference expands it. Match the current Task/Phase revision, dependencies and observed outputs before acceptance. A completed Task does not complete a larger goal with required work remaining; `malts_verify_task` or `task-verify` checks the current scoped proof without rewriting history.
