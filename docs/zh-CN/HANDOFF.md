# 交接

MALTS 交接帮助其他窗口或 Agent 理解项目目标、当前进度、实际证据及下一项具备条件的工作，用于跨中断接续。当前版本：**2.0.2**。交接是按需生成的接续视图，执行状态由所选任务服务维护。

## 默认文件名

默认 Agent 侧文件名为 `PROJECT_HANDOFF.md`。需要时可另建用户侧中文镜像 `项目交接.md`，仅在明确请求时生成。文件名是约定，不产生权限或状态权威。实际交接属于项目工作区，不能存入发布仓库或不可变安装。

文件名便于定位接续视图，生成与选择仍依实际用途。存在多份输出时，选择绑定当前任务/来源的视图，不能按最新文件名决定权威。翻译镜像标识来源，不另建任务状态。

视图存于稳定项目位置，链接较大产物/证据而非复制正文。安装代际只提供模板。这样 MALTS 更新后，项目仍能保留自己的原始交接资料继续工作。

## 规则

- 使用用户或项目的叙述语言，保留稳定协议字段和代码。
- 更新已有视图前，保全独有手工备注和原始来源。
- 不将秘密、凭据、原始会话转储或私有证据复制到公开交接。
- 另一执行者或窗口确需接续时生成，普通成功轮次无需交接。
- 区分事实、建议、未决决定和实际授权；“下一步建议”不授权执行。
- 从当前来源生成，旧摘要不能覆盖新工作或认证未知效果。

## 应包含内容

| 项目 | 内容 |
|---|---|
| 身份与时间 | 工作区、准确 Task/Phase 版本、来源身份、生成时间 |
| 目标与范围 | 原始/当前目标、保护对象、实际验收条件 |
| 进度 | 已交付结果与未完成事项，区别于活动记录 |
| 证据 | 检查及其适用输入版本，包括失败、跳过和未验证 |
| 恢复 | 检查点、未知操作 ID、相关宿主/写者事实、epoch 与累计预算 |
| 下一步 | 依赖、未决取舍、最小可执行接续 |
| 手工内容 | 再生成时须保留的独有观察和指令 |

`runtime/EN/templates/PROJECT_HANDOFF.template.en.md` 是起草参考。按实际接续保留足够信息，不复制全库或全历史。

可用交接区分观察结果与建议工作。迁移项目应说明保留了哪项接口、测试了哪些输出字节、哪些检查失败或不可用，以及未决写入是否可能已经发生。“大部分完成”不足以让后继执行。

以下是格式示例，方括号内的信息应从真实任务与观察取得：

```text
目标：迁移模块，保留经审阅公共接口。
合同：Task [ID/版本]，Phase [ID/版本]，计划 [路径/哈希]。
观察结果：实现 [输出身份]，检查 [实际结果]。
未完成：[未满足条件及其依赖]。
未知效果：操作 [原ID]，[重试前须取得的观察]。
恢复：检查点 [身份]，Host [实际状态]，预算 [累计消费]。
下一步：先对账效果，再执行指定剩余兼容检查。
手工备注：[保全来源身份及相关观察]。
```

不嵌入凭据、大段原日志或未解释内部历史。需要较大来源时，提供位置和适用证据身份。保留失败检查，不能将示例改写成全部成功。

## Plan Binding

记录所属 Phase、当前计划引用及准确 SHA-256、Task/Phase 版本、相关依赖版本，以及实质变化后所需检查。依赖摘要前核实际计划字节。已采用 v2 的工作使用当前阶段/任务服务；历史 Markdown Plan Recheck 不成为其写入权威。

依赖视图前核三种关系：当前任务定义、绑定的 Phase 版本和实际计划字节。交接生成后计划改变时，旧叙述仍可解释历史，但下一动作须使用新的审阅定义与绑定。

例如添加部署步骤会改变执行边界，即使大部分迁移正文相同。应修订受影响任务/阶段，不能追加一句话静默授权部署；阅读视图的文字修正也不自行修订可执行计划。

记录实质修订原因与剩余验收，使后继区分已批准和拟议变化，不将每条备注当当前权限。

## 控制对象的关联核对

已采用工作区接续前核 Boot、生命周期 discovery、workspace binding 和当前任务上下文。报告/交接描述事实，但不能替代事实。保留采用 seal、原始证据和未决效果；采用前资料只解释其历史合同，不能据此复活旧写入权威。

## 保全、预览与发布

当前服务可保全指定备注/文件，并预览有界交接。预览包含来源、token 和局部标记，不证明完整性或权限。受保护发布比较准确当前 Task 版本、来源 token、经审阅的已有输出及前像。失败沿原身份检查；缺失输出应使用独立范围的新建操作，不能盲目覆盖。

受保护流程分四步：先以准确来源哈希捕获经审阅手工备注或已有目标；再按当前 Task/版本和选定 note ID 预览；审阅完整结果及 source_token；最后使用捕获前像和明确发布授权写回该已有目标。

handoff.capture-file 在独占文件保护下观察已有文件并保全字节，不修改它。当前备注/捕获上限为 65,536 字节。捕获成功只适用于当时，发布仍比较当前目标。handoff.preserve-note 则记录控制端审阅的来源字节，source_ref 是来源说明，不是服务自动读取的路径。

发布只写派生视图，不产生 Task 执行 Grant。它拒绝局部预览、任务/token 变化、缺少选定目标前像或当前字节变化。中断后 handoff.inspect-publication 区分目标结果、前像和分叉字节，不重写。已有意图但缺可用当前回执时，沿同一 publication ID 检查，不能换 ID 重放。

## 接续

读取当前目标、任务状态和相关实际文件。依赖工作前沿原操作 ID 对账 UNKNOWN。PAUSED、租约到期、取消确认和传输退出不能证明所有写者停止。保持既有预算和后续工作。参见[使用指南](USAGE.md)、[状态合同](V2_STATE_CONTRACT.md)及[交接操作](V2_PREVIEW_USAGE.md#v2-handoff)。

后继先核运行时与工作区身份，再将交接的任务/计划引用与当前上下文比较。依赖执行前检查真实输出和原未决操作。保全备注可能真实，却描述较早来源状态。

事实不同则保留视图并说明差异，审阅来源后只刷新派生部分，不能回滚当前任务以迎合旧交接。手工文字与生成事实冲突时，保留两种来源并解决实质问题，不删除不利备注。

受保护捕获/发布实现见 [Handoff implementation](../../tools/v2_handoff.py)，当前入口见[控制端操作](V2_PREVIEW_USAGE.md#v2-handoff)。

## 工作区管理数据与迁移

普通新工作区通过 `workspace-init` 默认将任务库、受管证据和恢复资料置于所属 `.malts` 目录，显式外置布局继续受支持。安装更新不搬动已有项目。健康已采用库可经只读计划、备份恢复、当前效果审查和正式前向切换重定位；新 epoch 不恢复旧授权或验收，也不自动激活 Phase。旧库、外部历史引用和来源封存按实际依赖保留。操作与限制见[工作区管理与状态库重定位](MANAGEMENT_AND_RELOCATION.md)。
