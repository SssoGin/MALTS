# 交接

MALTS 交接帮助其他窗口或 Agent 理解项目目标、当前进度、实际证据及下一项具备条件的工作，用于跨中断接续。当前版本：**2.0.0**。交接是按需生成的接续视图，执行状态由所选任务服务维护。

## 默认文件名

沿用 Agent 侧名称 `PROJECT_HANDOFF.md`。需要时可另建用户侧中文镜像 `项目交接.md`，仅在明确请求时生成。文件名是约定，不产生权限或状态权威。实际交接属于项目工作区，不能存入发布仓库或不可变安装。

## 规则

- 使用用户或项目的叙述语言，保留稳定协议字段和代码。
- 更新已有视图前，保全独有手工备注和原始来源。
- 不将秘密、凭据、原始会话转储或私有证据复制到公开交接。
- 另一执行者或窗口确需接续时生成，普通成功轮次无需交接。
- 区分事实、建议、未决决定和实际授权；“下一步建议”不授权执行。
- 从当前来源生成，旧摘要不能覆盖新工作或认证未知效果。

## 应包含内容

| 项目 | 内容 |
|---|---|
| 身份与时间 | 工作区、准确 Task/Phase 版本、来源身份、生成时间 |
| 目标与范围 | 原始/当前目标、保护对象、实际验收条件 |
| 进度 | 已交付结果与未完成事项，区别于活动记录 |
| 证据 | 检查及其适用输入版本，包括失败、跳过和未验证 |
| 恢复 | 检查点、未知操作 ID、相关宿主/写者事实、epoch 与累计预算 |
| 下一步 | 依赖、未决取舍、最小可执行接续 |
| 手工内容 | 再生成时须保留的独有观察和指令 |

`runtime/EN/templates/PROJECT_HANDOFF.template.en.md` 是起草参考。按实际接续保留足够信息，不复制全库或全历史。

## Plan Binding

记录所属 Phase、当前计划引用及准确 SHA-256、Task/Phase 版本、相关依赖版本，以及实质变化后所需检查。依赖摘要前核实际计划字节。已采用 v2 的工作使用当前阶段/任务服务；历史 Markdown Plan Recheck 不成为其写入权威。

## Cross-Control Binding

已采用工作区接续前核 Boot、生命周期 discovery、workspace binding 和当前任务上下文。报告/交接描述事实，但不能替代事实。保留采用 seal、原始证据和未决效果；采用前资料只解释其历史合同，不能据此复活旧写入权威。

## 保全、预览与发布

当前服务可保全指定备注/文件，并预览有界交接。预览包含来源、token 和局部标记，不证明完整性或权限。受保护发布比较准确当前 Task 版本、来源 token、经审阅的已有输出及前像。失败沿原身份检查；缺失输出应使用独立范围的新建操作，不能盲目覆盖。

## 接续

读取当前目标、任务状态和相关实际文件。依赖工作前沿原操作 ID 对账 UNKNOWN。PAUSED、租约到期、取消确认和传输退出不能证明所有写者停止。保持既有预算和后续工作。参见[使用指南](USAGE.md)、[状态合同](V2_STATE_CONTRACT.md)及[交接操作](V2_PREVIEW_USAGE.md#v2-handoff)。
