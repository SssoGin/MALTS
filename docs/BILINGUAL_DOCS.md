# MALTS Bilingual Documentation and Templates

English and Simplified Chinese guides describe the same MALTS product, currently **2.0.2**.

## User Documentation

README.md and docs/ provide English guides; README.zh-CN.md and docs/zh-CN/ provide matching Chinese guides. Keep chapter purposes, examples, parameters and limits aligned. Implementation and actual evidence determine technical facts.

The English and Chinese entry points refer to the same workflows and exact command contracts. Relative links within docs/zh-CN stay within the Chinese guide set; source/schema links resolve to the shared package. A reader can therefore choose a language without choosing another implementation or installation.

For example, ToolRootDeepSeekHarness and the Host identity deepseek-harness keep their exact spelling in both language guides. Translating that identifier or inventing a Chinese command alias would make an otherwise understandable instruction non-executable. Translate the purpose while retaining executable identifiers.

## Runtime Templates

runtime/EN and runtime/CH contain Agent templates/checklists. Stable machine fields, commands and state codes remain unchanged. Structural checks do not prove translation quality.

## Canonical Project Files

Project-authored narrative and manual notes keep their original language. In adopted workspaces, the selected store/services own executable facts. Narrative controls and plans remain sources/views rather than a second localized state.

Narrative goals, plans, manual notes and observations can use the project's language. Their machine identifiers, state codes and source hashes remain exact. A translated quotation is a reading aid; it does not replace the original bytes bound by evidence or a plan.

When a current view is translated, preserve its source identity and task revision. If the source changes, review the translated view against the new facts before reuse. Do not keep one queue in English and a second queue in Chinese: conflicting definitions would leave continuation and acceptance without a unique owner.

## What Is Not Duplicated

Do not duplicate task stores, operation identities, budgets, acceptance, credentials or raw evidence for translation. A full translated report/handoff is optional and requested explicitly.

## Agent Behavior

Read one applicable language for the current purpose. Preserve authored content, resolve critical wording against actual contracts and review both versions when updating a shared protocol.

Use the selected guide language for explanation, and use the runtime's actual fields for effects. If a translated instruction conflicts with the loaded action contract, inspect the exact parameter schema and implementation before execution; language preference cannot change Host permission or state semantics.

Structural checks compare headings, paths and required protocol tokens. Semantic review checks whether the translated explanation retains prerequisites, outcomes, failure handling and limitations. Passing the first does not establish the second. Runtime template encoding and source-byte hashes must follow their actual contract rather than automatic editor normalization.
